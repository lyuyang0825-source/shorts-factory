# shorts-factory

**从一句选题到可执行的分镜包：钩子 → 六段叙事 → 分镜 → 口播/SRT → 多平台改版 → 合规检查 → 可渲染样片。**

[![ci](https://github.com/lyuyang0825-source/shorts-factory/actions/workflows/ci.yml/badge.svg)](https://github.com/lyuyang0825-source/shorts-factory/actions/workflows/ci.yml)
![python](https://img.shields.io/badge/python-3.10%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)

> 样片是**分镜渲染**（字幕 + 镜头卡），不是终版成片；它的作用是让剪辑、拍摄、运营在同一个时间轴上对齐，再替换成实拍或生成素材。
>
> 这是四个行业独立仓库之一 · [总览与另外三个产品](https://github.com/lyuyang0825-source/ai-industry-labs)

## 为什么做这个方向

短视频生产的瓶颈已经不是“能不能生成画面”，而是**有效成片率**：2026 年一季度上线的 AI 微短剧中，播放量破亿的头部作品占比仅 0.117%，大量内容是“无效产出”。

单条成本并不低：精品 AI 漫剧每分钟制作成本约 4000 元，普通质量也要 1500 元/分钟；反复抽卡、人工修复会继续叠加时间与人力。

真正的浪费发生在前期：脚本没有钩子、镜头没有信息增量、同一内容要手工改 3 个平台版本、发布前没人查绝对化用语。这个工具不解决“生成得多像”，只解决**“这一条值不值得做、每一秒拍什么、每个平台怎么改”**。

## 快速开始

```bash
git clone https://github.com/lyuyang0825-source/shorts-factory.git
cd shorts-factory

python3 -m shorts_factory.cli --brief samples/brief_zh_01.json --out-dir demo_out --render
python3 -m unittest discover -s tests      # 13 tests
```

无需第三方 Python 依赖；`--render` 需要系统安装 `ffmpeg` 与 Pillow，中文字体使用 Noto Sans CJK（找不到会回退到 AR PL UMing）。

## 两个样例，两种时长

| 样例 | 选题 | 时长 | 结果 |
| --- | --- | --- | --- |
| `brief_zh_01.json` | 熬夜后心慌，什么时候必须去医院 | 60s | 19 镜 / 60.0s / 口播 259 字 / 约 57.6s / 密度 4.3 字每秒 / 阻断 0 |
| `brief_zh_02.json` | 久坐腰酸，三个动作别做错 | 30s | 15 镜 / 30.0s / 口播 201 字 / 约 44.7s / 密度 6.7 字每秒 / 阻断 0 |

第二个样例是**故意给的“超载”输入**：201 字塞进 30 秒，必然语速偏快。工具不会偷偷加速，而是在 `pacing.note` 里明确提示“建议删减约 57 字，或把时长放宽到 44 秒”。这比生成一条听起来很顺、实际没人跟得上的视频更有用。

分镜表节选（60 秒样例）：

| 镜号 | 时间 | 段落 | 画面 | 口播 |
| --- | --- | --- | --- | --- |
| 1 | 0.0–4.6s | 3 秒钩子 | 真人半身口播，0.5 秒内出关键词大字 | 先别划走。熬夜后心慌，先记住判断顺序。 |
| 5 | 13.9–16.1s | 判断标准 | 信息图逐条弹出，关键数字放大 | 三个必须就医的信号： |
| 9 | 25.3–27.3s | 行动清单 | 手部演示 + 清单卡片 | 现在能做的三件事： |
| 19 | 56.6–60.0s | 行动号召 | 结尾定格，收藏/转发动效 | 收藏这条，转给经常熬夜的同事 |

## 时间轴怎么算

1. 按中文口播 **4.5 字/秒** 估算每句自然时长（单镜下限 1.6 秒，避免闪帧）；
2. 总时长不足目标时，把余量按段落权重分配成 **B-roll 素材位**（≥3 秒才建位）；
3. 总时长超出目标时，整体等比压缩，并给出“需删减多少字 / 建议时长放到多少秒”的提示；
4. 最后把浮点误差吸收到最后一镜，保证总时长严格等于目标。

六段叙事固定骨架：钩子（8%）→ 痛点（15%）→ 标准（29%）→ 行动（27%）→ 边界（13%）→ CTA（8%）。权重在 `planner.BEAT_SPECS`，可以按题材改，但总权重保持 1。

## 输入格式

```json
{
  "topic": "久坐腰酸，三个动作别做错",
  "audience": "每天坐 8 小时以上的办公室人群",
  "platforms": ["douyin", "kuaishou"],
  "duration_s": 30,
  "tone": "直接、可跟着做、不吓人",
  "key_points": ["先判断…", "三个动作…", "别做错…"],
  "cta": "收藏，下午三点跟着做一遍",
  "disclaimer": "科普内容不能替代面诊，疼痛加重请就医",
  "tags": ["#久坐", "#腰酸", "#办公室健身"]
}
```

## 多平台适配

| 平台 | 画幅 | 默认时长上限 | 重点 |
| --- | --- | --- | --- |
| 抖音 | 9:16 | 60s | 前 3 秒钩子、话题 3–5 个 |
| 视频号 | 9:16 | 60s | 标题更正式、封面字少 |
| 小红书 | 3:4 | 60s | 封面信息密度高、笔记化标题 |
| B站 | 16:9 | 180s | 横屏、标题可长、系列化 |
| 快手 | 9:16 | 60s | 口语化、直接给动作 |

每个平台输出独立标题、封面文案、话题与 ffmpeg 规格，不用一套通投。

## 合规检查

| 规则 | 检查 |
| --- | --- |
| C001 | 绝对化用语（最/第一/百分百/保证） |
| C002 | 医疗承诺（治愈/根治/替代就医） |
| C003 | 金融承诺（稳赚/保本/收益） |
| C004 | 医疗/金融题材缺免责声明 |
| C005 | 封面文案超过 12 字 |
| C006 | 时长超过平台上限 |
| C007 | 话题少于 3 个 |

合规结论分“阻断 / 提醒”，直接写进 `storyboard.md` 与 `compliance.md`。

## 当前限制

- 钩子是模板化候选，不替代编导对受众的直觉；真正有效的钩子仍需 A/B 实测。
- B-roll 只给“素材位与任务”，不自动生成画面；接生成模型时需另做素材一致性校验。
- 多平台标题是规则生成，未接入各平台实时热点与限流词库。
- 样片是卡片渲染，不能用来判断画面质感与表演。

## 路线图

- [ ] 钩子 A/B 评分：用历史完播数据训练排序，而不是固定模板
- [ ] 接入素材库：按镜头语义检索 B-roll，自动匹配时长
- [ ] 数字人口播：口型、停顿、重音与 SRT 对齐
- [ ] 平台规则热更新：限流词、时长、话题数量
- [ ] 数据回流：发布后 24h 完播/跳出，反推哪一镜该改
